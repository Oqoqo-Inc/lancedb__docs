[Lance REST Namespace](https://lance.org/format/namespace/rest/catalog-spec/?h=rest) spec
is an OpenAPI protocol that enables reading, writing and managing Lance tables by connecting
those metadata services or building a custom metadata server in a standardized way.

LanceDB OSS allows you to interface with Lance tables via the REST Namespace.
However, LanceDB's Cloud and Enterprise products provide an extended REST API with
additional endpoints for managing projects, tables, and data.
If you have specific needs or questions about the Enterprise/Cloud REST API Namespace,
please [contact us](mailto:support@lancedb.com).

## Authentication

<Badge color="blue">Cloud</Badge>
<Badge color="red">Enterprise</Badge>

LanceDB supports two primary authentication mechanisms for Cloud and Enterprise:

- **API key authentication** using the `x-api-key` header (recommended for quickstarts, smaller projects, and individual usage).
- **OAuth/Bearer token authentication** using the `Authorization: Bearer` header, typically integrated with an IdP or SSO provider (recommended for enterprise and production workloads).

All HTTP requests to LanceDB APIs must contain one of these authentication headers and must be encoded as JSON or Arrow RPC.

### API key authentication

Use an `x-api-key` header with your LanceDB Cloud/Enterprise API key:

```bash
curl -X GET "https://{db}.{region}.api.lancedb.com/v1/tables" \
   -H "Content-Type: application/json" \
   -H "x-api-key: LANCEDB_API_KEY"
```

The tutorial below demonstrates how to connect to LanceDB Cloud using the REST API with `x-api-key` authentication.

### OAuth/Bearer token authentication

For enterprise and security-sensitive environments, you can use OAuth/Bearer tokens instead of static API keys. In this model, your application obtains an access token from your IdP or OAuth server and sends it to LanceDB in the `Authorization` header:

```bash
curl -X GET "https://{db}.{region}.api.lancedb.com/v1/tables" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
```

When using the LanceDB SDKs, you can configure this pattern using header providers:

- **TypeScript**: `OAuthHeaderProvider` from `@lancedb/lancedb`, which accepts a token-fetching function and automatically refreshes the token before it expires.
- **Python**: `OAuthProvider` from `lancedb.remote.header`, which wraps a token-fetching callable and handles thread-safe token refresh.

See the **LanceDB Cloud Get Started** guide for end-to-end examples in Python and TypeScript using these providers.

### Get the API Key

1. Go to [LanceDB Cloud](https://accounts.lancedb.com/sign-up) and complete the onboarding.

![create](/static/assets/images/api-reference/create.png)

2. Let's call this particular **Project** `embedding`.
3. Save the API key and the project instance name: `embedding-yhs6bg`.

This is how the Project looks in the LanceDB Cloud Dashboard:
![projects](/static/assets/images/api-reference/projects.png)

4. In your terminal, check the existence of the remote **Project**. Specify the remote LanceDB **Project** `db` and `region`.

```bash
curl -X GET "https://{db}.{region}.api.lancedb.com/v1/tables" \
   -H "Content-Type: application/json" \
   -H "x-api-key: LANCEDB_API_KEY"
```

5. Now, create a **Table** to store data. Let's call it `words`.

```bash
curl -X POST "https://embedding-yhs6bg.us-east-1.api.lancedb.com/v1/tables/words" \
   -H "Content-Type: application/vnd.apache.arrow.stream" \
   -H "x-api-key: LANCEDB_API_KEY"
```
- the `db` is `embedding-yhs6bg` 
- the `region` is `us-east-1`
- the name of the table is `words`. 

6. Now check that the **Table has** been created: 

```bash
curl -X GET "https://embedding-yhs6bg.us-east-1.api.lancedb.com/v1/tables" \
   -H "Content-Type: application/json" \
   -H "x-api-key: LANCEDB_API_KEY"
```

You can always check from the LanceDB Cloud Dashboard:

![words](/static/assets/images/api-reference/words.png)

That's it -- you're connected! Now, you can start adding data and querying it.
